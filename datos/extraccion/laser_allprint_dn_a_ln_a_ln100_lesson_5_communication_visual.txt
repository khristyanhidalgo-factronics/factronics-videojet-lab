Using AllprintBasic
This program is designed for project engineers who want to connect the Smart Laser System via its serial
or digital interface to the customer's devices or control system.
The Smart can be programmed by special entries in the Smart database to react to the diverse signals of
the customer's hardware.
With this tool these entries, here called documents, can be generated, loaded, imported, edited, tested,
exported, saved and printed.
Document types
Customers can control the Smart via the serial interface or the digital interface. Since these interfaces are
different, the documents which describe these interfaces are different, too.
Generally documents consist of configuration elements and a basic - like language - AllprintBasic - which
defines the reaction of the Smart to events or messages from the customer.

Low level communication protocol
The task of this protocol is to separate a stream of characters, which are received by the serial interface,
into a message. Single characters are interpreted in a special way.
There are three protocols available:
The timeout protocol
The 3964R protocol
The EOTSUM protocol
These protocols can be selected in the upper part of a serial document by clicking on the configuration
element 'Protocol (Level 1)'.
For this exercise we will be using EOTSUM protocol only.
The timeout protocol
This protocol separates data streams by using timeouts. The timeout can bet set in units of 20 ms in the
upper part of a serial document by clicking on the configuration element 'Timeout Time'.
Receiving:
First of all the Smart Laser System awaits the first character of a message. After receiving it, a timer is
started to measure the time between two characters. If the timer reaches the timeout, any characters that
were received before this event are combined to one message.
Transmitting:
Messages are sent directly without any controlling.
The 3964R protocol
This communication protocol, which was first introduced by 'Siemens', provides a higher communication
security for data transmissions. The messages are included by predefined control characters and
transmissions are only possible after a special preparation between the Smart Laser System and the
customer's hardware before every transmission. Additionally a kind of checksum is transmitted to
recognize transmission errors.
For further information on the 3964R protocol please refer to a general description of the 3964R.

The EOTSUM protocol
This protocol manages a transfer of ASCII characters between a master and slave and offers a framing
and a simple checksum.
The master (i.e. host PC) frames each telegram with a "Start of Text" and "End of Transmission"
character. The transmission is completed by the transmission of the checksum cc. The protocol follows
the rule [STX] "mydata" [EOT] cc.
If the slave (i.e. Smart) receives the telegram and computes the same cc it replies with an acknowledge
[ACK], otherwise with a negative acknowledge [NACK].
If the cc was correct the slave can reply to the master using the command "Send". The answer is framed
with [EOT] and cc.
Example:
<STX>"mydata"<EOT>cc #sent by the host PC (master)
<ACK> #generated automatically by the protocol (slave)
126<EOT>cc #if the ALLPRINT Basic program reacts with send("126") to the incoming
"mydata"
The checksum is a simple 8 - bit addition including all control characters.
High level communication protocol
After the characters from the serial interface are separated into a complete message by the low level
communication protocol, the messages are relayed to this protocol level. Here the messages are
interpreted and assigned to Smart commands.
The AllprintBasic protocol
This protocol provides the greatest flexibility to adapt to the customer's specifications. With a special
AllprintBasic instruction string the reaction of the Smart Laser System to a message of the customer can
be programmed.
Example:
The customer wants the Smart Laser System to start if an "A" is sent to the Smart and to stop if a "B" is
sent. This can be implemented easily by using the following AllprintBasic instruction string:
If (Left(1) == "A") Then Start; Else Stop;
For an overview of the commands please refer to the section AllprintBasic instruction string.
AllprintBasic instruction string
In the lower part of a document the instruction string can be edited. It determines the reaction of the
Smart Laser System to a message from the customer. This message can be received via the serial or
digital interface.

debugging binary and other difficult data streams. It is far better for debugging comms
than Hyperterminal. It has no support for dialing modems, BBS etc - that is what
hyperterminal does.
• Text or Binary views of data
• binary viewed as hex, 8 bit, 16 bit, little/big endian, signed, unsigned, special fonts
• colorised: rx and tx data are different colors
• ansi terminal or plain text or binary modes
• protocol analyser / "port spying" mode
• fixed frame sizes/line lengths
• sync patterns with masks and xors
• data inversion
• full remote control through active X/ Windows Scripting
• extensive command - line control
• can be used for serial I/O component of other programs via activeX. Full support for
minimize,hide,iconize, tooltray
• special ascii+hex font to see hidden control chars
• capture to file, settable capture size or capture duration
• view and change control lines (cts,rts, dcd etc)
• easy to send binary sequ ences
• serial (comports) or telnet via tcp
• arbitary baud rates
• reset / power buttons for Pic Programmer
• hideable to run in invisible or on tool - tray
• can dump files to serial port
• Drives I2C and SPI chips via BL233

DTE stands for Data Terminal Equipment, which is usually a
PC.
Signal Definitions
The signals are described in terms of a PC (DTE) and a modem (DCE.) As mentioned
before, in the simple case an embedded system will only use RXD, TXD, and GND,
unless hardware handshaking is used.
• T ransmit D ata - PC's serial data output stream to modem
• R eceive D ata - PC's serial data input stream from modem
• GND - Signal ground
• C arrier D etect - tells PC that modem has good remote connection
• C lear T o S end - modem is ready to receive data from PC
• D ata S et R eady - tells PC that modem is ready
• D ata T erminal R eady - tells modem that PC is ready
• R equest T o S end - tells modem PC wants to send data
• R ing I ndicator - modem detected a ringing signal

External Template Selection
1 Preparation
In order to use the external template selection the laser system must be equipped with
two optional input modules (art. no. 65856). These input modules have to be inserted
between input module 6 and the termination module 7.
Additionally, a valid template list is required for using the external template selection.
2 Template List
In the Smart Graph software under Laser Operation - > Marking adjustment
you can create a template list using the templates existing in the laser system.
A template is assigned to a certain number in the template list (see below). The number
of the desired template is sent - e.g. by a PLC - binary coded to the digital inputs DATA
0 to DATA 7
and is taken over with the signal EXT_EVENT. The selected template becomes current
template of the laser system and can be marked on the product. This procedure is
called External Template Selection .
The dialog »Template list« contains the assignment of templates and template numbers
for the external template selection.
