3 .1 CLARiCOM Products
“The Claricom Package Coding Management System eliminates all potential errors of
printed information at source whether it is dates, batch codes or pricing.
It is the most cost effective and flexible system focused on ensuring accuracy on pack
and negates the need for camera based verification systems that are expensive, inflexible
and time consuming in set - up.
T he Claricom PCMS has been proven in the field to give real cost savings in time,
efficiency and labor and is "future proof" as new technologies are introduced to stock
handling and identification e.g. RFID tagging“.
3 - 4

• Field - Based Image Design
– Intuitive positioning and sizing of fields
– Field specific properties; x, y, size, font etc.
• Coder Independent File Format (CIFF)
– One design format used for all coder types
• Even images designed for a specific coder are stored in a generic
format
– Provides a superset of all known image properties
• Date Calculations
– Part of the overall design (not part of the individual fields)
– A single calculation can be used by many fields
• Allows multi - lingual dates / Allows a single date to be used for
barcodes and text
• Support for real - time coder features (such as time and counter fields)

3.1 9 CLARiTY Data File Support
This release adds support for CLARiTY Data files. This allows the printer to print a
sequence of images where part or all of the data to be printed for each print is sourced
from a text file. This allows unique traceability information to be printed at high
throughputs.
A CLARiTY Data file is a text file where each line of the text file represents the data for
one
print. Empty lines in the text file will be skipped. The CLARiTY Data file is installed in
to printer using a USB device. The file should be placed in the root of the USB drive and
named "CLARiTY Data File.txt". When the USB device is inserted a prompt will be
displayed asking whether to install the new data file (a warning will be displayed if a data
file is already installed and installing the new data file will cause entries in the old file to
be lost). If the operator opts to install the new data file, it will be copied off the USB
device onto the printer’s internal storage, and the file will be deleted from the USB
device. The prompt when a USB key is inserted may be disabled via CLARiTY
Configuration Manager, a new parameter has been added to the folder System / USB
called Prompt On CLARiTY Data File Detect which by default is set to 1:Yes to enable
the prompt. Setting this to 0:No will disable the prompt and prevent data files being
installed.
By default the format of the data file is expected to be plain ASCII text. The printer also
supports Unicode and UTF - 8 formatted text files. To change the file type the parameter
Imaging / CLARiTY Data File / Character Set needs to be set appropriately. To print the
data in the file an image needs to be designed in CLARiSOFT that uses the CLARiTY.
Encryption. Data File encryption component (available separately). This should be
applied to a Global Numeric counter field that uses Global Counter 14. The counter
should have a sufficiently large end value to print all lines in the text file, and the start
value must be set to "Last Value". Each time the count value increases, the printer will
read the next line of the file. The contents of the encrypted counter can be merged into
other fields such as barcodes.

3. 20 Using text files with clarity
Most commands return either the default success response or the default failure response
depending on whether or not the command was successfully executed.
The default success response is:
ACK<CR>
The default failure response is:
ERR<CR>
The examples given below use the character » to indicate data sent to the printer, and « to
indicate data being received from the printer.
For example:
»CAF<CR>
«ERR<CR>
means “the string ‘CAF<CR>’ was sent to the printer, which responded with the string
‘ERR<CR>’”.
Because the carriage return character resets the parser, it is recommended to send
the carriage return character before each communications session in order to clear
any unwanted data which may be in the parser’s buffer.
This example sends the parser reset character before sending two commands to the
printer:
»<CR>
»JDU|data|<CR>
«ACK<CR>
»PRN<CR>
«ACK<CR>
