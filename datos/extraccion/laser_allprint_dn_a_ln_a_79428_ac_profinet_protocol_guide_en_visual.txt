How to work with commands
A command value can be sent from PLC to laser via the data block «Transmitted *COMMAND*».
When a command has been sent, the caller need to check the result in the data tags "Cmd Response" and "Cmd Executed". While the laser is executing a command, the tag "Cmd In
Progress" will reflect the command in progress.
Before a new command can be send to the laser, "NoOperation" (0) must be sent. Example: "No Operation" -"Start Marking" - "No Operation" - "Stop Marking".
When the laser finished processing, check the result in the tags "Cmd Executed" and "Cmd Response". Please refer to the data definition table for command- and respond values.

General
Before a job can be used to set marking data (variable content) from a PLC, the
job needs to be created upfront e.g. with TCS+.
The user needs to setup the job according the specifications for the product to
mark: place elements (like barcode, text fields, etc.) where needed and assign
fields (text variables) for the content to set via PLC.
Make sure that the length of job names, field names, etc. do not exceed the maxi-
mum allowed length and that names consist of characters only from ASCII
charset.
Allowed ranges are given in the tables below. If values are out of range, it is not
possible to address these variables from PLC.

1 Introduction
PROFINET
PROFINET is the open Industrial Ethernet standard of PROFIBUS and
PROFINET International (PI) for automation based on Industrial Ethernet and
uses TCP/IP, UDP and IT standards.
PROFINET uses a real-time model for communications known as PROFINET IO,
which is similar to PROFIBUS DP. PROFINET IO is generally referred to as just
PROFINET.
PROFINET offers scalable communication for different applications in industrial
automation:
PROFINET IO uses a view of distributed I/O similar to PROFIBUS DP. IO con-
trollers (e.g. PLCs) run an automation program, IO devices (e.g. absolute en-
coders) are remotely assigned field devices, and IO supervisors (e.g. program-
ming devices) are used for commissioning and diagnostics.
The engineering of PROFINET IO is done similar to PROFIBUS. The field buses
(i.e. Ethernet topologies) are assigned to control systems during configuration.
The IO device is configured in the actual system based on the contents of its GS-
DML file.
After completion of the engineering, the installer loads the data for the expansion
into the IO controller (PLC) and the IO controller assumes data exchange with the
IO device.
An IO device is addressed within PROFINET (and also possibly by external IT
components) through its IP address and device name.
Process data will be exchanged between the Controller and the Device via cyclic
messages at the desired speed. Data can also be queried in acyclic way from an
IO Supervisor system.
General
This document describes the usage of the PROFINET interface on the laser. With
this interface, the laser is able to operate as a field bus device controlled by a
PLC. The basic functionality provided by the PROFINET protocol is to start and
stop laser markings, to select marking templates (jobs) and line/product detection
configuration.
Furthermore, the PLC can set variable content for a job to mark, do adjustments
on the job, like position offset, scaling and rotation. For general operation, the
laser state and current laser errors and warnings can be read out.
