Barcode Sizing
Set the preferred emulation sizing for barcodes.
CLARiTY printers have resolutions of 300dpi (Thermal Transfer heads), 180dpi (Piezo - Crystal
heads) and variable (Thermal Ink - Jet heads). If we are emulating a 203dpi Zebra we could be
asked to print half of one dot, which is not possible.
• Favor Smaller Barcodes (0) – will mostly make the barcode smaller if we can’t be exact due to
resolution differences.
• Balanced (1) – will round to the nearest size (larger or smaller) if we can’t be exact due to
resolution differences.
• Favor Larger Barcodes (2) – will mostly make the barcode larger if we can’t be exact due to
resolution differences.
• Default: Favor Smaller Barcodes.

Label Configuration
• The label configuration allows for setting label parameters for printing. The Label Width and Label Height
needs to be set correctly when the image is being rotated in the printer.
• Each of the Label Configuration options has a “Use Emulation Value” option or “Use Printer Value”.
• The “Use Printer Value” will ignore the value sent by ZPL. This option is available because we found
through development that some packages gave us incorrect label dimensions, and in order to rotate we
need know the correct dimensions so the fields are put in the correct place.
• By default, the LabelWidth and LabelLength are set to “Use Printer Value” while the HorizontalFieldOffset
and LabelOrigin default are “Use Emulation Value”.
Note: If you receive barcode out of limit adjust your label
length and label width .

Troubleshooting
• Ensure you are using the correct printer mode.
• Ensure you are using the correct DPI.
• Ensure the correct width and length in the ZPL or SATO label
configuration section of Config.
• Check the printer ZPL or SATO emulation port
• Check the printer IP address
• Check the PC IP address
• Once the sending software is connected verify the com port
on the printer is ready
• Read the Zipher Text Communication Protocol manual
Confidential - Company Proprietary

No job or missing job when job sent
• Check that you are sending to the correct printer IP Address and Port from
the sending software.
• Check the network connection, IP address, subnet mask and port. The IP
address and subnet mask will need to be in the same domain for the printer
and data sending device.
• Ensure that the connection is in an ‘open state’ to receive data for the desired
emulation type.
• Ensure that the emulation data for the label design sent has label start and
end delimiters and that it contains well - formed valid data that results in a
printed output.
• Ensure that the correct protocol command codes have been sent.
• Check which mode the printer is in, downloaded jobs will appear in the ‘Jobs’
list if successful and will need to be selected to print, if select only is applied,
then the list of jobs will only appear in the job queue list.
Confidential - Company Proprietary

Label printed but no image
• Check the label on clarity before printing to see if an image is represented
correctly.
• If the image is displayed in clarity there may be an issue with the physical
printer setup including the ribbon or label setup or in the print setup including
print speed, force etc.
• If there is no image shown in clarity check that the print length and print width
are set to the size of the label in clarity and the emulation data sent, if the
image width or length are too large and the orientation is at 90 for example the
image may be drawn off the label.
Confidential - Company Proprietary

The label image is too small or too large
• Check the resolution of the printer in respect to the emulation configuration
and ensure that if sending an image for a 200dpi printer that the printer is
configured for 200dpi or likewise for 300dpi or 600dpi.
• Check the resolution factor is set to full (ZPL).
Confidential - Company Proprietary

The label image has started printing part way
down the image and not from the top
• Check the label length setting in clarity and in the emulation data sent.
• Check any offsets or label home settings in clarity and in the emulation data sent.
• The image will align to the baseplate, so at 90 a label design with a length smaller
than the physical label will print at the bottom. Likewise if the label design length is
greater than the physical label length the image will again be aligned to the
baseplate pushing the top of the label design off the label.
Confidential - Company Proprietary

The label image is printed to one side or the
other
• Check the physical setup of the labels and ribbon on the Integra.
• Check for any offsets or label home settings and reset, in clarity or in the label
data sent.
• Check for print width settings as any image smaller than the label will align to
the baseplate if no offsets are applied.
Image is printed in the wrong rotation
• Set the ‘ JobOrientation ’ in the ‘imaging’ menu to the correct orientation required
0, 90, 180 or 270.
Confidential - Company Proprietary

The barcode printed is larger than expected
• Set the barcode sizing to ‘favor smaller barcodes’, a barcode which would be
partially printed, due to positioning or off the label will not be drawn. A ‘barcode
out of limits’ warning should be displayed.
There is a barcode out of limits warning or the
barcode is not drawn
• Set the barcode sizing to ‘favor smaller barcodes’, a barcode which would be
partially printed due to positioning or positioned off the label will not be drawn
and a Barcode out of limits warning will be displayed.

I can’t communicate using ZPL emulation
• If the ZPL connection is lost and attempts to regain communication fail: this is likely due to
more ZPL jobs being sent than the printers own Print Queue Limit can handle but the printer
has a TCPIP card to buffer overflow jobs. This is likely on the (9550 Integra). For example,
the following situation:
• ‘ MaxQueueLength ’ set to 5, ‘ PrintLimitMode ’ set to ‘Use ZPL Supplied Print Limit’ & ZPL
‘ PrintMode ’ set to ‘ DownloadSelect&DeleteAfterUse ’.
• 20 ZPL jobs can be sent but only 6 will appear in the CLARiTY printers Image Update
Queue (the currently printing job and the 5 queued up). The other 15 will be buffered in
the printers TCPIP card (which can theoretically buffer an unlimited number of jobs).
Imagine the printers TCPIP card as a secondary ‘overflow’ buffer that fills up the printers
own Image Update Queue as it is depleted.
• If ZPL connection is now lost it cannot be regained until the TCPIP card buffer is empty.
Confidential - Company Proprietary

ZPL connection appears to be open but
communication is not possible
• If the ZPL connection appears to be open but communication is not
possible, e.g. ~HS does not return anything. This is likely due to more ZPL
jobs being sent than the printers own Print Queue Limit can handle and
there is no TCPIP card to buffer overflow jobs. These overflow jobs
‘disappear’. This is likely on printers other than 9550.
Confidential - Company Proprietary

Both of the above scenarios should be due to a
combination of three following things being set at the
same time:
• ZPL PrintLimitMode has been set to “Use ZPL Supplied Print Limit”.
• ZPL PrintMode has been set to something other than “Download Only” (i.e.
“Download & Select”, “ Download,Select&DeleteAfterUse ” or “Select Only” (don’t
use database)”.
• Printers own queue is subsequently filled up.
• Set Print Queue length in CCFG Imaging/ UpdateQueue (Default is 1, max is
250).
• View at the User Interface Tools/Diagnostics/Control/Image Update Queue.
Confidential - Company Proprietary

To overcome these either
• Change the Print Mode to Download Only – that will mean you can have any
number of jobs on the coder but you will need to select the job manually or via
comms;
• Change the Print Limit mode to “Unlimited prints” – this will always overwrite the
current job with the new job (as there was no Print Quantity allocation);
• Increase the Queue Size – this is by default set to 1 but can be increased to a
maximum of 250. Even so, once the queue is full you will experience the same
issue.
• Note: if you are constantly printing whilst downloading, you may never fill the
queue.
• Repeatedly print until the CLARiTY printers own print queue starts to deplete.
• Re - power the printer to clear the print queue.
